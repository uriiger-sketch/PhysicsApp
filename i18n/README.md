# Languages

The app is one page per language, all generated from one master:

| File | What it is |
|---|---|
| `physics_game_v28.html` | the **Hebrew master** — the only file where code, physics and Hebrew text are edited |
| `physics_game_<lang>.html` | a **generated** language edition — never edit it by hand |
| `i18n/<lang>/config.json` | the language: output file, direction, the few exact code/HTML patches |
| `i18n/<lang>/*.json` | its translations, one file per area (content of a subject, its simulations, the interface, …) |
| `i18n/<lang>/glossary.md` | the binding glossary and style guide of that language |
| `tools/i18n.js` | extract · check · build · stats |
| `tests/check_i18n.js` | the edition shows no Hebrew anywhere and no placeholder, with no page error |
| `tests/check_i18n_badges.js` | the edition shows the same SI unit badges as the Hebrew (the build works them out from the Hebrew wording) |
| `tests/check_i18n_progress.js` | progress, XP and every quiz answer are the same after switching language with the 🌐 menu |
| `tests/check_i18n_labels.js` | no canvas label is lost in translation (a label that does not fit is not drawn), every slider at both ends |
| `tests/_lang.js` | gives every subject test the words of the page's language, so the same test runs on any edition |

The 🌐 menu in the header (`APP_LANGS` in the master) lists the languages; a
choice opens the same topic and tab in the other page and is remembered by
`index.html`. Progress is shared: localStorage is the same, and quiz answers
follow their question in every language (the build writes the master's quiz
identities into each edition as `QID_TABLE`).

## How a text becomes a translation unit

`tools/i18n.js` parses the master's script and takes every expression that
produces text with Hebrew in it — a string, a template literal, or a chain
`'…' + x + '…'` — as **one unit**, so a translator sees a whole sentence.
Everything inside it that is not literal text (a formula `M(…)`/`tex(…)`, a
number, a variable, a nested expression) is a placeholder `⟦0⟧ ⟦1⟧ …`. The
translation may move placeholders but keeps each exactly once, so formulas and
computed numbers can never be damaged by a translation. Units are keyed by a
hash of their Hebrew text: identical texts share one translation, and a text
that changes in the master becomes a new unit (the old translation is kept in
`_stale` for reuse).

Strings the code compares or searches for are logic, not display text; they
are listed in `i18n/<lang>/_logic.txt` and never translated.

## Translation files

```json
"3fa9c1e2b7d4": {
  "he": "גוף נמצא ב־⟦0⟧. מה פירוש הסימן השלילי?",
  "en": "A body is at ⟦0⟧. What does the negative sign mean?",
  "at": ["CONTENT['kinematics.distance-time'].quiz[0].q  L2451"],
  "ph": ["tex('x = -3\\,\\text{m}')"]
}
```

Edit only the language value (`"en"`) and, if useful, `"note"`. `he`, `at`
(where the text is used), `n` (how many places) and `ph` (what each
placeholder is) are regenerated by `extract`. `"keep": true` keeps the Hebrew
(only for the language menu's own name, עברית). `"reviewed"` records review
passes, e.g. `"reviewed": ["physics", "language"]`.

## Workflow

```sh
node tools/i18n.js extract en     # after the master changed: new texts appear empty
node tools/i18n.js stats en       # what is left
node tools/i18n.js check en       # guards: placeholders, Hebrew left, HTML tags and
                                  # attributes (errors); numbers, maths symbols (warnings)
node tools/i18n.js build en       # writes physics_game_en.html
node tests/check_i18n.js en       # no Hebrew anywhere in the edition
APP_FILE=physics_game_en.html node tests/smoke.js   # any generic test, on the edition
```

A change to the master is a change to every edition: after it, run
`extract`, translate the new units, `build`, and commit the master, the
translation files and the rebuilt editions together. An untranslated unit
falls back to Hebrew (and `check_i18n` fails), so nothing is ever blank.

## How a language is made

Every language goes through the same four stages, each by its own specialists,
recorded per unit in `"reviewed"`:

1. **Translation**, one translator per area, against the binding glossary.
2. **Physics review**, one physicist per subject: every unit against the
   Hebrew — meaning, terminology, quiz keys and distractors, problems, canvas
   labels. Errors found in the Hebrew are fixed in the master, which fixes
   them for every language.
3. **Scientific-educational language review**, an editor per group of
   subjects: idiom, one voice across the edition, the style guide, interface
   microcopy, inclusive language.
4. **QA**: the whole test suite on the built edition (`APP_FILE=…`), plus the
   edition tests above.

`node tools/i18n.js stats <lang>` shows, per area, how many units are
translated and reviewed. The English edition: 8331 units, all translated and
all reviewed for physics and for language.

## Adding a language

1. `i18n/<lang>/config.json` — copy `en`'s; set `lang`, `name`, `file`, `dir`
   (`rtl` for Arabic, otherwise `ltr`) and the `htmlPatches`/`codePatches`.
2. Add it to `APP_LANGS` in the master and to the map in `index.html`.
3. `node tools/i18n.js extract <lang>`, a glossary, then the four stages above;
   `build`, and the whole test suite on the edition.
