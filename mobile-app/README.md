# Physfun · פיזיכיף on iPhone, iPad and Android

This folder turns the game into apps for the **App Store** and **Google
Play**. The game is the Hebrew master `physics_game_v28.html` and the English
`physics_game_en.html`, with the landing page `index.html`, all at the
repository root. It uses [Capacitor](https://capacitorjs.com) 8: native
projects that show the pages, bundled inside the app, in the system's web view.

The pages at the root stay the one source; the app is rebuilt from them.

**Every change to the app is made in Hebrew and in English, both in the
website's pages and here** (see `CLAUDE.md` at the repository root).
- A text or behaviour change goes into the master.
- It is translated and built into the English edition (`i18n/README.md`).
- It reaches the app with `npm run build`.
- What the stores show (`store/`) is kept in both languages too.

| Ready here | What only you can do |
|---|---|
| Android Studio project (`android/`), Xcode project (`ios/`) | Developer accounts: Google Play ($25 once), Apple Developer Program ($99 a year) |
| The app's web bundle, built and checked (`npm run build`, `npm run check`) | The signing keys, kept by you, never in the repository |
| Icon (from your design), launch screens, feature graphics, 48 screenshots (`store/`) | Running the uploads: the *Store apps* workflow builds, signs and uploads on GitHub's machines (no Mac needed) once your App Store Connect key is in the repository's secrets |
| Listing texts in Hebrew and English, privacy policy, questionnaire answers (`store/`) | Creating the store entries, uploading, pressing *Submit* |

## How the app differs from the website

`scripts/build.mjs` copies both editions into `www/` with three changes. Each
is an exact substitution it counts, so a change in the master that it does
not expect stops the build instead of shipping:

1. **KaTeX is inside the app** (`www/vendor/katex@0.16.9/`, the npm release
   byte for byte, still held to the pages' SRI hashes). The app works fully
   offline and contacts no site at all, not even jsDelivr.
2. **The CSP** names that path on the app's own origins (`https://localhost`
   on Android, `capacitor://localhost` on iOS) where the site names jsDelivr.
   The preconnect to jsDelivr is gone. Everything else in the policy is the
   site's, including `connect-src 'none'`.
3. **🖨 (print a progress summary) is hidden**, and `window.open` returns
   nothing. A phone's web view has no print dialog, and on Android the blank
   window would replace the course.

**The start page is the website's own `index.html`, byte for byte**, so the
site and the app open by one rule:
- the language of the last session, which every page records;
- on a first visit, Hebrew in Israel, by the device's time zone or an Israeli
  region in its languages (he-IL, en-IL, …);
- English everywhere else, and wherever the place is not known.

And the native side:
- **Android back button:** steps back through topics and tabs, as the game
  intends (it records each in the history), and leaves the app only from the
  first page (`MainActivity.java`).
- **Screen edges:** the system bars sit on the course's dark ground with light
  icons, and nothing hides under the notch, the home indicator or Android's
  bars.
- **Pinch-zoom:** on, as on the site.
- **Sensor lab:** the motion sensor works without a permission prompt. iOS
  apps may read the accelerometer, and Capacitor grants the web view's request.

`npm run check` tests all of this in Chromium, with the bundle served at the
app's own origin and every other address cut off. The repository's own test
suites also pass on the copies in `www/`, for example
`APP_FILE=mobile-app/www/physics_game_en.html node tests/smoke.js` from the
root.

## The app's identity

| | |
|---|---|
| App ID (Android package, iOS bundle ID) | `com.physfun` |
| Store names | פיזיכיף (Hebrew) · Physfun (English) |
| Name under the icon | פיזיכיף on a Hebrew device · Physfun on all others |
| Icon | `resources/icon-source.jpg`; `npm run art` makes every size from it |
| Version | the game's `APP_VERSION`: 28.41 → Android versionCode 2804100, iOS build 28.41.0 |

**The app ID is permanent once the app is in a store.** Android requires at
least two parts separated by a dot, so `Physfun` alone is not possible there;
`com.physfun` is the shortest valid form. To choose another before the first
upload:
1. Set `appId` in `capacitor.config.json`.
2. Run `npm run build`. It writes the ID into both native projects. Android's
   Java package, `com.physfun`, can stay as it is.

The version follows the game: every `npm run build` reads `APP_VERSION` from
the master. To upload the same game version a second time, for a native-only
fix, run `APP_BUILD=1 npm run build` (then 2, 3, …, up to 99).

## Build it yourself

You need:
- Node 22 or later;
- for Android, [Android Studio](https://developer.android.com/studio) (it
  brings JDK 21 and the Android SDK);
- for iOS, a Mac with Xcode 26 or later. Since April 2026 the App Store
  accepts only builds made with it.

```sh
cd mobile-app
npm ci --ignore-scripts   # Capacitor and KaTeX, exactly as locked
npm run build             # www/ from the root pages, copied into android/ and ios/
npm run check             # optional; needs the root's dev tools: at the root, npm ci
                          # and npx playwright install chromium
```

Run `npm run build` again whenever the game changes. The native projects
take their web assets from it; those copies are generated and not committed.

## Google Play, step by step

1. **Account.** Create a developer account at
   [play.google.com/console](https://play.google.com/console).
   **A personal account created after 13 November 2023 must run a closed test
   with at least 12 testers for 14 days before it can publish to everyone.**
   Plan for it. An organisation account is exempt.
2. **Upload key, once.** Android Studio creates it in step 3 (*Create new…*).
   Or on the command line:
   ```sh
   keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
   ```
   Keep the file and its passwords safe, outside the repository, because
   every update is signed with it. Google keeps the app's own signing key
   (Play App Signing); a lost upload key can be reset through Play support.
3. **The bundle (`.aab`).** Run `npm run build`. Then one of:
   - **Android Studio:** *Open* `mobile-app/android`, wait for Gradle sync,
     then *Build → Generate Signed App Bundle or APK → Android App Bundle*.
     Choose the key and *release*. The file lands in
     `android/app/release/app-release.aab`.
   - **Command line:** write `android/keystore.properties` (git ignores it):
     ```properties
     storeFile=/full/path/to/upload-keystore.jks
     storePassword=…
     keyAlias=upload
     keyPassword=…
     ```
     Then run `npm run android:bundle`. The file lands in
     `android/app/build/outputs/bundle/release/app-release.aab`.
   - **No Android Studio:** the *Store apps* workflow below.
4. **Play Console → Create app.**
   - App name `פיזיכיף`, default language Hebrew (`iw-IL`), *App*, *Free*.
   - **Store listing:** the texts in `store/listing.md`, and the images in
     `store/google-play/`: icon, feature graphic, phone screenshots, 10-inch
     tablet screenshots. Then *Manage translations* to add English (`en-US`,
     name `Physfun`) with its own texts and screenshots.
   - **App content:** every answer is in `store/answers.md`. The privacy-policy
     address works once this folder is on `main`, because GitHub Pages serves it.
5. **Testing → Closed testing:** create a release, upload the `.aab`, and add
   your testers' emails. After the closed test, *Production → Create release*,
   using the same file or a newer build.

## App Store, step by step

No Mac is needed: the *Store apps* workflow builds the app on GitHub's macOS
machines, signs it with Apple's cloud signing and uploads it, and it uploads
the whole listing in Hebrew and English. Your part is once, in Apple's sites
and in GitHub:

1. **Register the bundle ID.** developer.apple.com → Account → Certificates,
   Identifiers & Profiles → Identifiers → **+** → App IDs → App:
   description `Physfun`, Bundle ID *Explicit* `com.physfun`, no capabilities →
   Continue → Register.
2. **Create the app.** App Store Connect → Apps → **+** → New App: platform
   iOS, name `פיזיכיף`, primary language Hebrew, bundle ID `com.physfun`, SKU
   `physfun-ios`, Full Access → Create.
3. **An API key for the workflow.** App Store Connect → Users and Access →
   Integrations → App Store Connect API → Team Keys → **+**: name `GitHub`,
   access **Admin** (cloud signing needs it) → Generate. Download the key, an
   `AuthKey_XXXXXXXXXX.p8` file (Apple lets you download it only once), and
   note its **Key ID** and the **Issuer ID** shown above the keys.
4. **Your Team ID.** developer.apple.com → Account → Membership details.
5. **Four repository secrets.** github.com/uriiger-sketch/PhysicsApp →
   Settings → Secrets and variables → Actions → New repository secret:
   - `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID`;
   - `ASC_KEY_P8`: the whole text of the .p8 file, its `BEGIN` and `END`
     lines included. On a phone, rename the file to `.txt` to open and copy it.
6. **Run the workflow.** Actions → Store apps → Run workflow, with *iOS* and
   *App Store listing* ticked. It uploads:
   - the build, which TestFlight shows after Apple's processing;
   - the listing in both languages: names, subtitles, descriptions, keywords,
     promotional texts, URLs, categories, review notes and 24 screenshots.

   Nothing is submitted for review.
7. **In App Store Connect, what only its forms take:**
   - App Privacy → Get Started → *No, we do not collect data from this app* →
     Publish;
   - Age Rating: None / No throughout (4+);
   - Pricing and Availability: Free;
   - App Review Information: your name, phone and email (the notes are
     already there);
   - Copyright: `2026 <your name>`;
   - the version page → Build: the uploaded build;
   - Add for Review → Submit to App Review.

**With a Mac instead:**
1. Run `npm ci --ignore-scripts && npm run build` in `mobile-app`.
2. Run `npm run ios:open`.
3. App target → Signing & Capabilities → Team.
4. *Any iOS Device* → Product → Archive → Distribute App → App Store Connect →
   Upload.

Then do steps 1, 2 and 7, typing the listing from `store/listing.md`.

## The Store apps workflow

`.github/workflows/store-apps.yml` runs on GitHub's machines:
- **On every pull request that touches the app or the game:** both apps are
  compiled, unsigned (iOS with Xcode 26 on macOS 26, Android with SDK 36), and
  the bundle is checked (`npm run check`), so a change to the site that would
  break the store apps shows up before it is merged.
- **By hand (Actions → Store apps → Run workflow):** each is a tick box:
  - the iOS upload;
  - the App Store listing (fastlane 2.241.1, a fixed version);
  - the Android App Bundle on a draft release, signed when its four secrets
    are set.

  The secrets it reads are listed at the top of the file. It never submits
  anything for review.

The App Store screenshots are 1290 × 2796 and 2048 × 2732. App Store Connect
takes these sizes in its required 6.9-inch and 13-inch slots, and every version
of the upload tools recognises them.

## Updating the app later

1. Change the game at the root as always: the Hebrew master, its English
   translation and the rebuilt edition, a new version.
2. Run `npm run build` in `mobile-app`. The new version is picked up.
3. Build and upload as above.

If the icon changes, replace `resources/icon-source.jpg` (the design on a light
background, as given) and run `npm run art`. It rebuilds every icon, the
launch images, the feature graphics and the pages' favicon file,
`resources/favicon-64.png`. The favicon then goes into the `<link rel="icon">`
of `index.html` and the master as a data URI.

For new screenshots, run `npm run screenshots` (after a build).

Maintenance:
- Capacitor updates: `npm install @capacitor/core@<v> @capacitor/cli@<v>
  @capacitor/android@<v> @capacitor/ios@<v>`, then `npm run build`.
- KaTeX follows the pages: the build stops with the exact command when the
  pages' KaTeX version and this folder's differ.
- To get Dependabot's bump PRs for this folder too, add an `npm` entry with
  `directory: /mobile-app` to `.github/dependabot.yml`.

## Good to know

- **Progress:** progress in the app is the app's own. It is not shared with
  the website, which keeps its own in the browser. Within the app, both
  languages share it, as on the site.
- **Status:** both native projects are generated by Capacitor's CLI and
  configured, and the *Store apps* workflow compiles both on every pull request
  that touches them. Before submitting, test the app on a real phone:
  TestFlight on iOS, the closed test on Android.
- **Secrets:** keystores, `keystore.properties`, `.p8` and `.p12` files are
  git-ignored here. Never commit them; the repository is public.
- **Licences:** the third-party licences travel inside the app,
  `www/licenses/NOTICE.txt`. They cover KaTeX (MIT), the Heebo and Rubik fonts
  (OFL) and Capacitor (MIT).
